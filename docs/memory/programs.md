Hub for milestone M3's program work. Schema in [[db]]; built in [[session-11]] and [[session-12]].

- **Programs and versions** ([[M3-01]]): one draft per program and frozen published versions. `save_program_draft` replaces the whole draft; `publish_program` freezes it and opens a copy as the next draft. The first version is live today in India; later ones from tomorrow.
- **Schedule** ([[M3-05]]): `packages/core` `programDay`, `sessionsOn`. The India date of joining is week 1 day 1, so the builder's "Day 1 to 7" counts from the athlete's start, not weekdays.
- **Builder** ([[M3-02]], PR #25): `/coach/programs`, `/coach/programs/new`, `/coach/programs/[id]`. The client keeps the whole draft and sends it as JSON; `apps/web/src/lib/program-draft.ts` mirrors `valid_prescription` (load uses the database's text rule, not floating point). "Unpublished changes" compares the draft's sessions with the live version (`sessionsKey`). The builder warns before leaving with unsaved changes and remounts after a save (keyed by `updated_at`).
- **Invites** ([[M3-03]], PRs #24 and #26): one active 32-hex code per program. `/coach/programs/[id]/invite` (copy, WhatsApp, joined list, reset with a confirm screen) and the public `/join/[code]`. Joining needs sign-in, a finished sign-up (step 2), the athlete role, and a published program with a coach; a removed athlete cannot rejoin. Link origins come from `apps/web/src/lib/site-origin.ts`.
- **Enrollments and access** ([[M3-04]], PR #27): `coach_can_read(athlete)` is the one rule for a coach reading an athlete's data: an active enrollment in a program the caller owns, plus the coach role. Policies on `profiles`, `athlete_prefs` and `athlete_basics` call it. `leave_program` (athlete), `remove_athlete` (owning coach), `my_programs()`. Screens: `/account/programs` with a leave confirm; Remove on the coach's joined list with K-ConfirmRemove.
- **Versions in effect** ([[M3-06]], PR #28): publishing freezes `title`, `summary` and `weeks` on `program_versions`. `programs` holds only the coach's working values and only its coach can read it (the public policy was dropped). `version_in_effect(program, date)` in SQL and `versionOn` in `packages/core` share one rule: the newest published version whose first day has come. `my_programs` and `invite_info` use today's version.
- **Today** ([[M3-06]]): `/today` picks the version per date, so a version starting tomorrow shows from tomorrow; it loads drills only for today's sessions. Empty state: paste an invite link (`lib/invite-code.ts` reads links inside chat messages too). Each session card has Start, Continue or Done (M3-07).
- **Session logs** ([[M3-07]], PR #29): `session_logs` (one per athlete, session and date), `item_logs` (per drill or exercise), `set_logs` ([[M3-08]], PR #30). Clients never write them: `log_drill`, `log_set`, `finish_session` and `save_session_note` check `scheduled_session` (the caller's active enrollment, the version in effect, week 1 day 1 on the start date, up to today). The athlete reads their own for good; a coach reads them through `coach_can_read` **and** `owns_program`. Item and set logs follow the parent's policy.
- **Player** (`/session/[id]?date=`, full screen in `(athlete)/(player)`): round timer (`packages/core/src/round-timer.ts`), wake lock, per-drill log; the set logger for `sets` items with last time (`lastTime`), the next target (`nextTarget`) and a 90 s rest. It is keyed on completion because Next keeps a visited page's state. Today shows Start, Continue or Done.
- **Summaries** ([[M3-09]], PR #31): `/session/[id]/done` in `(athlete)/(shell)`, numbers from `summarise()` in `apps/web/src/lib/session-summary.ts`; the note to the coach saves on the log.
- **Metrics** ([[M3-10]], PR #32): rules in `docs/plans/m3-metrics.md`. `packages/core/src/metrics.ts` (records, hard sets, adherence %, skill rating) and SQL `adherence`, `hard_sets_per_muscle`, `skill_ratings` (security invoker, so RLS decides who sees what). M3-11 and M3-12 must use these and not compute their own.
- **Coach access rule (fixed in [[session-13]], PR #33):** data tied to one program (logs, and feedback in M3-13) opens to a coach only through `coach_reads_program(athlete, program)`: an active enrollment in THAT program. `coach_can_read` (any of the coach's programs) is for athlete-wide data such as the profile. Programs are private: only the coach and athletes who joined read versions, sessions and drills (`ever_enrolled`); others see a program only through `invite_info`. Feedback also needs an athlete-own policy, so it survives leaving ([[M3-13]] carries the pgTAP check).
- Helpers: `isUuid` and `ownProgram` in `apps/web/src/lib/programs.ts`; `coachWithProgram` and `newPage` in `apps/web/e2e/helpers.ts`.
